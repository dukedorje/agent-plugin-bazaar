## Blind pass (written before design.md/tasks.md, persisted at the spawn dir)

From the Why, the living verbs spec (`spec.md:430`), and the cited code alone, I pinned ten concerns the author had to have answered:

1. Split `available` into *configured* / *executable* / *health* — today `ladder.py apply_env` collapses the first two into one bool.
2. Health must be advisory: no priority reorder, no beating a human pick (living spec line 435–436; `human_override: always wins`).
3. Executability must be permission-aware — `requirement_met("codex")` goes true on an OpenAI key alone, but `run_openai` is a read-only chat adapter, so a *write* route must not light up on key-only.
4. The default reviewer must be a different family than the author; removing Fable/Sol-arch is only safe if the codex-down fallback is Grok, never a Claude reader on a Claude author.
5. One concrete-version registry — `CLAUDE_MODELS`, `FAMILY_FROM_INTERFACE`, and `EFFORT` drift across two files today.
6. Migration aliases must keep in-flight old ids resolving (this very packet carries `interface: opus-4.8`).
7. Bound the fallback chain; `after` handoff is currently unbounded.
8. Refuse paid synthetic probes; derive health from passive infra signals.
9. "Unknown" health must mean *try it*, not *skip* — otherwise passive health silently reorders.
10. Tradeoff: passive health is only as fresh as recent traffic, so TTL expiry must fail **open** (back to usable), not closed.

## Steelman — the contract answers each

The design and the `verbs` delta answer all ten, and not by accident:

- **(1)(3)** "model routes separate configuration, executability, and health" with the explicit clause *"an OpenAI API key without a write-capable harness SHALL NOT make a write route executable"* and the scenario *API key is read-only executability*. Exactly the hazard, named and forbidden.
- **(2)(9)(10)** "skip degraded routes without reordering the remaining priorities", "Verified and unknown routes SHALL remain eligible", "Explicit human selection SHALL not be blocked by health" (+ warning), and the decay rule *verified → unknown* (usable) rather than *→ degraded*. TTL fails open. This is the core of my take and it is airtight.
- **(4)** The standalone "second-family advise is spawned, not parked" requirement plus the review-family boundary: Claude author → skip Opus → Astra else Grok 4.7. Removing Fable is what makes the default non-self-review.
- **(5)** "one family registry that maps each family to the concrete model id", and task 5 removes silent stale-model fallbacks in spawn.
- **(6)** "Historical route ids MAY remain migration aliases for one release" — covers `--after`, stored/in-flight packets, muscle memory.
- **(7)** "at most two fallback hops" in both design and delta.
- **(8)** "Only infrastructure evidence SHALL affect health"; health store is runtime scratch (not project memory — also clears the exit test); task 9 verifies Grok 4.7 "without requiring a paid recurring probe".

Contrast acceptance holds: every `if_false` clause (self-review by default, API-only chat as write-capable, health reordering/overriding humans, stranded in-flight ids) is explicitly prohibited, and the full `if_true` set is implementable with Fable and Sol-arch removed. I accept.

## Watch during act (non-blocking — not owed boxes)

These do not gate the contract; they are implementation seams the act worker should close, each already defensible because the human-pick escape always exists:

- **Author-family detection.** The cross-family scenarios presume the author's vendor family is known at assign time. For `run next=advise` it is inferable from the landed act; for a standalone `advise`/`consult` it must be supplied as a resolver input. Define that input explicitly so "skip the author's family" is deterministic, not guessed.
- **Credential identity without leaking the key.** Health keyed on "adapter + concrete model + credential identity" and auth-failure reset "until credential identity changes" needs a *non-secret* fingerprint (e.g. org id or a salted hash prefix). `spawn.py` is careful never to log the key today — keep that invariant; do not derive identity from the raw secret.
- **spawn interface→model map.** Migration aliases cover ladder route-id resolution, but `spawn.py CLAUDE_MODELS` resolves the concrete model from `interface`. Ensure a packet whose `assignee.interface` is a retired version string (e.g. `opus-4.8`) still resolves for the one-release window, so the alias promise reaches the launcher boundary and not just the ladder.
- **Doc consistency.** `docs/LEARNINGS.md` records "Terra then Sonnet (known)" (2026-09-02); the new order is Sonnet then Terra. Task 6 names "skills, references, specs, ADRs, and tests" — fold LEARNINGS.md and README routing claims into that sweep so no stale order survives.

None of the above changes a SHALL. Accept — proceed to act.
