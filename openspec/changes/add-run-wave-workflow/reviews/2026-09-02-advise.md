## Independent take (written before opening design.md / tasks.md)

1. Pin: children are `agent()` calls that read the packet path and
   write an agent-surface result face to their spawn dir; the workflow
   returns paths, never content. Otherwise `workflow` becomes the
   second RPC ADR-001 forbids.
2. Pin: after join and before persist, `git status --porcelain` on
   HEAD is diffed against the union of the wave's declared `paths`;
   undeclared dirt is a red for the node whose packet is nearest,
   never silently left for the next wave.
3. Pin: two children share one working tree. Focused verify inside
   child A can go red from child B's half-written files. A wave red is
   not trusted until re-verified sequentially after join (or classify
   treats wave red as retry-serial once).
4. Pin: per-child timeout in the rhai → `infra-red` face for that
   child only; the conductor `release`s that node and still persists
   the siblings that passed.
5. Refuse: any `isolation: "worktree"` (or equivalent) in the rhai
   `agent()` opts; any `conductor.py isolate` or `persist` from inside
   a child; any packet whose `do_not` grows a commit exemption to make
   HEAD sharing "safe".
6. Refuse: `take` after launch. The spec says take-then-launch; the
   code path must not be "launch, then take on first result".
7. Concern: `dispatch()` counts every `in_progress` node against
   `max_inflight`, including read nodes (advise). A lingering read
   lease makes `free` 1 and the wave degenerates to one.
8. Concern: `pick_wave` order is `dispatchable + capped` first-match.
   A path-less node at position 0 blocks the whole wave; at position
   1+ it is skipped. Deterministic and correct, but the card should
   say why a node was not in the wave.
9. Tradeoff accepted: whole-packet prefix disjointness on
   `constraints.paths` with directory-shaped paths will rarely form a
   wave of 2. Honest cost of parking worktrees and deferring the
   organizer; slice one buys the plumbing, not the throughput.
10. The delta's order "persist, then classify" commits red work to
    HEAD. Consistent with `act`'s commit-on-red, but must be stated
    as chosen, not accidental.

## One real tradeoff

**Whole-packet disjointness vs. throughput.** Slice one fans only
packets whose full `constraints.paths` are prefix-disjoint. With
directory-shaped paths (`plugins/intention/skills/run/`,
`openspec/changes/<id>/`) most sibling nodes of one change collide,
so the wave of 2 fires mostly across changes, not within one. The
alternative — the ultrapilot-shaped owned/shared/boundary split — buys
throughput by lying to the mutex unless take, verify, and close all
see the same projection (Sol's dissent, `design.md`). Taking the
smaller, honest set first is the right order: the plumbing (write-set
before pick, cap after disjoint, release on infra, sequential persist,
`{id,success}` return) is exactly what the organizer will need, and
none of it has to be undone. The cost is that the EYES box may be
hard to hit naturally — a real two-node wave needs two dispatchable
writes in different trees. Stage one deliberately.
