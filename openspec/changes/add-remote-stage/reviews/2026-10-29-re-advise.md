## Blind take

Written before opening design.md or tasks.md, from proposal Why/What, the remote-stage delta, the living agent surface and taskPacket schema, and the two cited functions.

1. Pin staging between a successful idle check and write_prompt, inside run_pi's existing session lock.
2. Preserve absent-stage and empty-array behavior, including the existing prompt-file copy and single paste.
3. Extend the closed taskPacket schema with an optional array of closed entries; require non-empty src/dest strings and boolean delete when present.
4. Validate the entire declaration before any entry runs; malformed input must neither disappear into the absent-stage path nor authorize pruning.
5. Pin runner inputs to the entry, the pane's configured transport, its session name, and access to the spawn timeout; default delete to false.
6. Execute entries in declaration order and stop at the first failure; refuse to write the prompt or submit after that failure.
7. Require an independent pre-submit time bound because run_turn starts its existing clock only after submit.
8. Convert missing runner, timeout, launch failure, and transport failure into a distinct stage failure, not run_pi's generic session-unreachable mapping.
9. Preserve finally-based unlock on all stage outcomes, and run nothing when the session is locked or the composer is dirty.
10. Accept the tradeoff of a fail-closed hook before the copy runner exists; require later focused evidence, without importing rsync implementation into this contract review.

## Comparison with the prepared design

The design answers the ordering and isolation concerns directly. The stage seam is after the successful idle check and before write_prompt, within run_pi's existing lock. That matches the live code: run_turn currently checks idle before writing the prompt (`plugins/intention/scripts/pi_tmux.py:265–281`), and run_pi releases the lock in finally (`plugins/intention/scripts/spawn.py:598–616`). The declared session and transport remain those used for the paste. No new harness lifecycle is needed.

The runner contract is sufficiently pinned for the next implementation: one call per entry, declaration order, normalized boolean delete, selected transport and session, zero/non-zero result, and first-failure stop. The timeout is the spawn's timeout_sec, default 600 seconds, owned by the runner. The implementing seam must make that value available to the runner; the precise Python signature remains an implementation choice. Since the contract describes individual calls, I read this as the bound for each runner invocation, not a shared deadline for all entries plus the later turn.

Failure classification is explicit where the live adapter currently lacks it. The existing turn clock begins after submit (`pi_tmux.py:285`), and generic error or unknown turn status maps to pi-session-unreachable (`spawn.py:636–642`). The new contract instead requires missing runner, non-zero result, timeout, launch failure, and transport failure at the stage boundary to produce pi-stage-failed before either write_prompt or submit. The design also preserves finally-based unlock. These are obligations for the act, not claims about the current implementation.

The packet boundary is coherent with the closed taskPacket schema. Design Validation and Schema require an optional array of closed objects, non-empty src/dest strings, and strictly boolean delete when present. Validation covers every entry before copying a usable declaration. An invalid declaration must retain a failure state through dispatch, so filtering it out cannot accidentally select the absent-stage path. Unknown fields, missing dest, and string delete fail closed. Omitted stage and an empty array preserve existing behavior. The schema and contract documentation edits are explicitly still owed.

## Steelman and tradeoff

The strongest objection from my blind take is that runner-owned timeout enforcement cannot stop a runner that ignores its contract. The design explicitly acknowledges that limitation. Requiring a second adapter cancellation framework would enlarge this hook into process supervision before the copy runner exists. I accept the narrower boundary: a conforming runner must enforce timeout_sec, and the adapter must normalize both its failure return and launch/timeout/transport exceptions while releasing the lock. A fake merely returning non-zero does not, by itself, prove the eventual copy runner enforces elapsed time; that responsibility also follows the runner into add-rsync-before-keys.

A second concern is that a hook with no production runner cannot perform a useful copy yet. Failing a declared stage rather than pasting is the correct intermediate behavior and preserves the dependency on add-rsync-before-keys. No copy command, destination invention, implicit pruning, or block-store claim is needed to accept this contract.
