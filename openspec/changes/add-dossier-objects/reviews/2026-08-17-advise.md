## Steelman against

Do not add an eighth kind. A dossier is a document face of an
intention that has not split yet. Living `working-method` already
says documents are how objects are shown, not a parallel store
(`openspec/specs/working-method/spec.md:75-79`). ADR-001 says
anything that cannot accept a packet is a document, a meeting, or a
bigger prompt (`docs/contracts/agent-surface.md:32-33`). Taskmaster
already has the graph: “A project is that graph with a public
address” (`docs/INTENT.md:12-13` in the sibling sketch). Gathering
could be an unsplitted intention plus notes. A new kind is the
failure mode this change exists to prevent — just earlier.

That steelman loses. Host-only naming would violate ADR-006. Stuffing
gather / cite / promote into `working-method` would remake the novel
`extract-working-method` existed to split. An eighth kind plus a
`dossier` capability, with Project and Values *not* kinds, is the
honest cut. The tighten that dossier is not an agent is correct.

## One real tradeoff

**Kind vs stage.** Dossier as a kind makes gather and promote
addressable. It also invites a type for every later stage. The
fence that keeps this from spreading is: Project is the named graph,
Values are preferences, documents stay a face. Hold that fence in
ADR-007. Do not grow kinds in `add-dossier-promote`.

## Findings

1. **Blocking — what promote creates.** A dossier is not an
   intention (`specs/dossier/spec.md:10-16`). A project “SHALL be
   the named graph an intention already is”
   (`specs/dossier/spec.md:19-23`; same claim at
   `specs/working-method/spec.md:6-7`). Promotion “addresses that
   graph” (`design.md:22-24`, `32-35`) and the scenario only
   requires “a project address exists” (`specs/dossier/spec.md:25-30`).
   The dossier has no graph and is not an intention. Act is told it
   “does not reopen” settlements (`design.md:3-4`). So
   `add-dossier-promote` will invent whether promote mints or
   selects an intention whose graph then gets the public address.
   Name that here.

2. **Nit — values at split.** “Breakable into intentions together
   with those values” (`specs/working-method/spec.md:9-10`,
   `specs/dossier/spec.md:33-36`) sits on the kinds requirement, not
   a MODIFIED split requirement. The scenario says they stay
   preferences, not a new kind (`specs/working-method/spec.md:38-43`).
   A hostile reading still makes them work nodes of kind `work node`
   labelled “value,” which would enter the ready-set. Say they are
   not work nodes and do not enter the ready-set.

3. **Nit — who shows the address.** “A project’s identity SHALL be
   its public address” (`specs/dossier/spec.md:56-58`) is a
   definition, not a mint protocol. ADR-007 should say the host
   (Taskmaster) shows the address; this marketplace does not mint
   URLs and does not touch IdentiKey.

## What is solid

- Dossier is a work object **and** a `dossier` capability; fold
  materializes it. Same parent-first pattern as
  `extract-working-method`.
- Project is not a ninth kind. Matches Taskmaster INTENT.
- Values are named preferences, not a score runtime. “Value Function”
  is speech.
- Promote cites; the gathering stays. Matches `bazaar-db8.4`.
- Self-description is not identity.
- Packet / result stay ADR-001. Dossier is not an agent (`b4ed6ef`).
- No framework SHALLs. Stack stays in sibling sketches.
- MODIFIED kinds requirement pastes the living “Status in a path”
  scenario. Journey and out-of-scope are honest. Hygiene is green.
