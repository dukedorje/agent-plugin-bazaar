## Blind take (written before opening design.md, tasks.md, steer.md, delta)

Read only: proposal Why/What, `verbs/spec.md` (take/max_inflight/ladder reqs),
`conductor.py`, `run/SKILL.md`, LEARNINGS:42, LEARNINGS:50.

1. PIN — capacity must derive from **held act leases** (`status: held`) scoped by an
   explicit campaign id, never from global bead `in_progress`. Bead status stops
   being a slot signal entirely (proposal What bullet 5); `dispatch` at
   conductor.py:140-154 is the exact site.
2. PIN — the campaign id must cross **every** command boundary explicitly:
   `run` → `ready`/`wave`/`take` as a flag/arg, and be written into the lease.
   A fresh `conductor.py` subprocess cannot read this tab's harness-local pin. If
   the design leans on the pin implicitly anywhere, that is a send-back
   (acceptance if_false names this).
3. PIN — write-set collision stays **global** over all held leases regardless of
   campaign; preserve the empty-paths → `flying_unknown` global block so an
   unknown write-set still fails safe.
4. PIN — define no-campaign / legacy lease semantics explicitly. A null-campaign
   held lease must still count for capacity **somewhere** (fail toward
   over-count) and **always** for collision — never become invisible to every
   campaign. Old leases pre-date the campaign field.
5. PIN — held-lease mutex needs atomic create (O_EXCL) or `take` is TOCTOU:
   `take` calls `dispatch` to check the slot, then writes its own lease; two
   concurrent takes can both see a free slot. Today `bd --claim` gives some
   atomicity; a plain file write to a shared dir does not.
6. REFUSE — no reaping story for a stale `held` lease (crashed worker). Today the
   bead / `release` resets `open`; a leaked `held` lease would consume a slot
   forever, which is worse than the status quo. Owe a staleness/expiry rule.
7. REFUSE — reading the real `.spawns/leases/` dir while in `--inventory`
   (hermetic-test) mode. The lease source must be injectable or `ready`/`take`
   tests stop being isolated.
8. TRADEOFF — scoping capacity per-campaign removes the accidental machine-wide
   throttle the global bead count provided: N concurrent campaigns now permit
   N×`max_inflight` workers. Correct per the goal, but the design should say so
   and consider whether a global ceiling is still owed.

Acceptance turns on: leases (not status) drive both the capacity read and the
collision read; campaign id is explicit across boundaries; legacy/no-campaign is
safe. These are questions the author must have answered, not a rival design.

## Comparison and steelman (after reading design.md, tasks.md, steer.md, delta)

The design answered the blind take on every load-bearing point. Steelmanning each:

- **PIN 1 (leases, not status) — answered.** design.md "Separate the three
  states" isolates lease-held-editing from bead progress; the delta's
  `max_inflight caps campaign act leases` requirement says global bead
  `in_progress` SHALL NOT consume slots, with the "Unrelated project tracking
  does not exhaust a campaign" and "Status without a lease consumes no slot"
  scenarios. Directly retires the conductor.py:140-154 conflation.
- **PIN 2 (explicit id, not the harness pin) — answered, and it is the headline
  decision.** steer.md "Campaign scope source: explicit campaign id (user)";
  design.md "avoids coupling scheduling to a harness-local session-pin file …
  works when a foreign harness receives a packet"; delta "`run` SHALL pass the
  pinned intention/root id as an explicit campaign id to … `ready`, `wave`, and
  `take`." Threads the boundary the acceptance if_false warned about.
- **PIN 3 (collision global) — answered.** delta "Overlapping write-sets across
  all held leases SHALL stay `deferred`, including leases belonging to other
  campaigns," with the dedicated "Cross-campaign overlap remains deferred"
  scenario. steer recorded this as the auto-decided collision boundary.
- **PIN 4 (legacy/no-campaign) — answered deliberately.** design.md "Legacy
  lease records without a campaign identifier remain visible to global collision
  safety; they do not silently consume a named campaign's slots"; tasks line 9.
  My instinct was to fail toward over-counting; the author resolved it the other
  way with global collision as the correctness net. Defensible: a lease owned by
  no current campaign should not eat a current campaign's allowance, and no write
  can collide undetected. Steelman holds.
- **TRADEOFF (loss of the accidental global throttle) — acknowledged.** design.md
  "Two campaigns can use their own worker allowances concurrently." N campaigns
  now permit N×`max_inflight`; proposal out-of-scope keeps `max_inflight`
  precedence/default fixed, so no new global ceiling is owed here. Intended, not
  an oversight.

Verdict: **accept**. The contract cleanly separates campaign focus, held act
leases, and bead tracking; same-campaign leases consume capacity, unrelated
status does not, all held leases still protect paths globally, and command
boundaries plus legacy behavior are explicit — matching every if_true clause and
dodging every if_false clause.

### Carry into act (clarify while implementing; not send-back gates)

These are implementation-clarity items inside the accepted contract, not holes:

1. **Preserve the unknown-write-set fail-safe.** conductor.py today treats an
   in-flight node with empty `paths` as `flying_unknown` and blocks all ready
   dispatch. When the collision read moves to held leases, a `held` lease with
   empty `paths` must keep triggering that global block. The delta scopes *how*
   capacity/collision are derived, not the disjointness algorithm — keep
   `paths_overlap`/`flying_unknown` behavior intact for leases.
2. **State `take`'s slot-check + lease-write atomicity.** `take` calls `dispatch`
   to confirm a free campaign slot, then writes its own lease. Within one
   sequential conductor loop this serializes, but two conductor processes on the
   *same* campaign could both observe the last slot free and both write leases,
   exceeding the cap. If concurrent same-campaign conductors are out of scope,
   say so; otherwise the lease create should be atomic (e.g. O_EXCL). Today
   `bd --claim` masks this; the lease model should not lose it silently.
3. **Keep the lease source injectable for hermetic tests.** `ready`/`wave`/`take`
   accept `--inventory` for isolated runs. The new lease read must not fall back
   to the real `.spawns/leases/` in inventory mode, or the regression coverage in
   tasks (status-without-lease, release, cross-campaign overlap) stops being
   isolated. A `--leases-dir` (or equivalent) resolves it.
4. **Optional: a TTL/reap for stale `held` leases.** A crashed worker leaves a
   `held` lease that now consumes a campaign slot. This is not a regression —
   today a crash likewise leaves the bead `in_progress` counting against the cap
   — and the lease already records `taken_at`, giving cleaner material for a
   future expiry. Noted, not owed for this change.
