## Independent take, recorded before design.md and tasks.md

1. Pin `src` to the conductor and `store` to the session machine; never reinterpret an existing conductor path.
2. Pin exactly one source selector and an explicit destination, with whole-declaration validation before any copy can start.
3. Pin store execution to the pane's existing transport and host; refuse a second host, harness, or attachment operation.
4. Require evidence that the store resolves onto the intended kind of mounted filesystem; an existing empty mountpoint directory is insufficient.
5. Keep idle check, session lock, ordered execution, and first-failure stop across both source kinds.
6. Preserve `pi-stage-failed` for copy, mount, launch, transport, and timeout failures, with neither prompt write nor submit.
7. Keep pruning opt-in per entry, and prevent a failed mount check from pruning destination contents.
8. Pin directory/content and path-quoting semantics so local and SSH store copies mean the same thing.
9. Bound mount inspection and copy together; preserve existing prompt files on failure and release the lock on every exit.
10. Accept the tradeoff of requiring a pre-mounted store to avoid attachment orchestration, but refuse success on an ordinary directory or a conductor fallback.

## Comparison and steelman

author correctly separates attachment, host allowlisting, and tag selection

The living stage-before-paste and runner-boundary requirements already supply

The strongest case for acceptance is that “guest mount” already means an actual

not resolve the literal fold conflict or distinguish a mounted store from an
existing directory left behind when mounting fails. Those two gaps remain
material even under that charitable reading.

## Required amendments

1. **Reconcile the entire declaration and runner contract.** The delta modifies
   `Stage declarations are checked` and `Rsync runner`, but leaves living
   `Stage declaration` (`openspec/specs/remote-stage/spec.md:17`) requiring
   `src` on every entry and `Runner boundary` (`:94`) requiring a normalized
   `src` argument. Folding the proposed delta therefore leaves contradictory
   requirements for a valid store-only entry. Add complete MODIFIED blocks for
   both, preserving all existing ordering, transport, prune, timeout, and
   failure clauses. Explicitly carry exactly one source selector to the runner.
   Record the corresponding implementation/check scope: the closed packet
   schema (`docs/contracts/agent-surface.schema.json:321`), agent-surface stage
   description, `validate_stage`, packet-to-spec propagation
   (`spawn.py:319`), `run_turn` normalization (`pi_tmux.py:335`), and default
   runner registration (`spawn.py:597`). Current code being src-only is expected
   before act; the problem is the missing reconciled contract and explicit
   implementation coverage, not that the feature is unbuilt. A focused
   packet-to-turn check should exercise store-only and mixed-source lists,
   reject both/neither selectors and a malformed later entry before any copy,
   and retain absent/empty and legacy-src behavior.

2. **Make missing-mount failure distinct from missing-path failure.** The new
   `Session store copy` success scenario (`specs/remote-stage/spec.md:40`)
   requires only that `store` exists; its missing-mount scenario (`:48`)
   requires that the path be absent. An unattached share can leave an existing
   empty directory. Copying that directory can return zero and, with `delete:
   true`, prune the destination before pasting. Specify the readiness evidence
   that must hold on the session machine before any copy or prune. State
   whether `store` is the mount root or may name a descendant, and distinguish
   the extra store mount from the guest root: the design records that `/`
   itself is virtiofs, so a filesystem-type check alone is insufficient.
   This need not select a host prefix or tag, nor implement attachment. Add a
   fake mount-inspection case with an existing but unattached directory and
   `delete: true`; it must start no copy, preserve destination and prompt,
   submit nothing, and report `pi-stage-failed`. Pair it with a successful
   mounted-store case. A plain temp-directory copy test alone cannot prove
   this boundary.
