## Independent take — written before opening design, tasks, or delta

1. Pin explicit user invocation as the entry condition for the ten-phase factory.
2. Pin the default route to `intend` for unrelated planning requests.
3. Pin `disable-model-invocation: true` even if the PARKED banner is removed.
4. Pin one named OpenSpec change directory as the planning session's document authority.
5. Pin phase narrative to proposal, optional design, and capability deltas rather than a parallel plan.
6. Pin phase progress and resumption to tasks checkboxes with an unambiguous change identity.
7. Pin preservation of the existing phase instruction files and the ten-phase workflow.
8. Refuse creation or continued dependence on `docs/sprints/`, `.omc/sprint-plan/`, or `phase-state.json`.
9. Refuse a partial MODIFIED replacement that loses the unprompted-invocation guard or silently expands sibling scope.
10. Tradeoff: shared OpenSpec documents remove duplicate state but require explicit mapping of phase outputs and restart behavior.

## Comparison and steelman

The author answers the central storage concern: phase narrative maps to
OpenSpec documents, progress becomes tasks checkboxes, one verb-led change
id replaces sprint numbering, and both legacy directories are forbidden.
The MODIFIED block preserves the phase files and
`disable-model-invocation: true`. Its replacement of the historical PARKED
wording is intentional and justified by the explicit revival request.

The strongest case for acceptance is that the explicit-intake scenario and
design already require a planning session that names or uses the factory.
Likewise, an architecture ADR or a child bead can be a canonical downstream
artifact rather than a second plan store. Those are reasonable intentions;
the normative wording needs to express them consistently before fold.

## Owed corrections

1. **Make invocation consistently explicit.** The MODIFIED requirement says
   the factory SHALL be intake whenever the user asks for “a planning
   session,” and the unprompted scenario excludes all such sessions from its
   guard. Design instead requires a session that names the factory and sends
   unrelated work to `intend`; the explicit-intake scenario is similarly
   narrower. `disable-model-invocation` alone does not resolve those
   contradictory instructions. Qualify both broad references so a generic
   planning request cannot authorize Phase 0. Preserve the default route in
   the requirement without requiring the revived description to retain its
   old PARKED wording.
2. **Reconcile the phase map with the exclusive write contract.** The delta
   says the skill SHALL “write only under” this change directory and the
   design says every phase writes there, yet phase 2A also writes an ADR to
   `ARCHITECTURE.md` and phase 2B produces child beads or child changes. State
   whether those are deferred handoffs or explicitly scoped non-plan
   outputs, and make the design and delta agree. Keep plan narrative and
   progress exclusively in the current change; keep story-bead implementation
   with `update-sprint-plan-beads`. This does not require another plan store.

Resumption and restart semantics should be made concrete during implementation
using the existing flags and the tasks cursor. That is the cost identified in
the blind take, not a demand for a new state mechanism or an additional blocker.
