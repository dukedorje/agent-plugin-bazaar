## Verdict

Send-back. The face, authority, and anti-goals are right. The delta
is stale against living ADR-007: a paste can mint work nodes that
never cite a dossier.

## Steelman against

Do not name a parse face. Paste is a convenience; intend plus beads
already produce work nodes; a host table of parsed records is store
number four under another name. ADR-006 already forbids a
Taskmaster-only object model
(`openspec/specs/taskmaster/spec.md:22-29`).

That steelman loses for the same reason `dossier` exists. Without a
named face, `add-paste-grammar` invents the mapping and the leftover
`task` table (`src/lib/server/db/schema.ts:3-7` in taskmaster-web)
becomes the product. Naming “existing objects, kernel authority,
cards are not `/`” is the right cut.

## One real tradeoff

**Two categories vs one mixed document.** Independent mappings
(gathering → dossier, task → work nodes) keep the grammar small.
Duke’s actual paste is one document with both. After ADR-007,
intentions that come out of a gathering must cite it
(`openspec/specs/dossier/spec.md:57-66`). Independent mappings
drop that trail. Prefer a slightly thicker face over silent
provenance loss.

## Findings

1. **Blocking — mixed paste has no provenance.** A task or
   intend-dag category “SHALL map to work nodes”
   (`specs/dossier/spec.md:5-7`). A gathering category “updates a
   dossier’s self-description or citations”
   (`specs/dossier/spec.md:17-22`). Those are independent. Living
   law: each emerged intention SHALL cite the dossier
   (`openspec/specs/dossier/spec.md:59-63`). `design.md:3-4` says
   act does not reopen settlements. `add-paste-grammar` would invent
   whether a mixed paste’s intend-dag items cite the dossier from
   the same paste.

2. **Blocking — intend-dag is not only work nodes.** ADR-007:
   what comes out of a dossier is an *intention* (then its graph).
   Mapping an intend-dag section only to work nodes
   (`specs/dossier/spec.md:6-7`, `design.md:8-10`) skips emerge
   and can create nodes with no intention and no cite.

3. **Nit — SHALL in reasoning.** `design.md:15` says a TUI-local
   DB “SHALL not be a source of truth.” Reasoning carries no
   `SHALL` (ADR-002). The living delta at
   `specs/dossier/spec.md:46-50` already has the requirement.
   Drop the word from `design.md` when amending; do not copy it
   into ADR-008 as a second SHALL pile.

4. **Nit — new item vs attribute.** The attribute scenario assumes
   “the work node already has” the field (`specs/dossier/spec.md:31-35`).
   Create-on-paste can wait for `add-paste-grammar` if finding 1–2
   name emerge.

## What is solid

- Face of existing objects, not a new document kind.
- Kernel tracker is authoritative; TUI-local DB is rejected.
- Leftover `task` table is not this face.
- Cards / dossier are not ready-set rows; `/` stays the ready-set;
  signal still means READY (`specs/taskmaster/spec.md:3-9`).
- Attributes vs bytes; bytes wait on `bazaar-ja7`.
- TUI is a sibling client, not an agent host.
- No Ratatui / SvelteKit / drizzle SHALLs in the deltas.
- Journey and out-of-scope are honest. Hygiene is green.
