# update-frontier-preparation

> **ACTIVE BUILD**

**Rigor:** change

## Why
Early activation lets downstream nodes execute assumptions that upstream
work has invalidated. Campaign permission should survive routine learning,
while each node's implementation contract is prepared when it becomes ready.
The user approved this direction and implementation in chat.

## What
- Require just-in-time preparation for act and every wave member.
- Let change apply recorded, bounded campaign activation to ready nodes.
- Surface preparation on run cards and invalidate obsolete advise accepts.

## Impact
- Capabilities: MODIFIED living-specs; ADDED verbs requirements.
- ADRs: no new packet schema or topology.

## User journey & surfaces
From /run, “run this whole intention” records bounded campaign authority.
As dependencies land, change reconciles each next contract and activates
within that grant. Missing authority leaves PENDING; changed commitments
return to the human. Existing /wait and /ask boundaries still stop.

## Out of scope
- Automatic semantic analysis inside the Python scheduler.
- New packet schemas, stores, or CLI activation flags.
