## Comparison and steelman

The design answers the central concerns correctly: stage after idle detection and before write_prompt under the existing lock; propagate the declaration through cmd_stage; extend the closed packet schema; keep the living agent-surface spec a pointer; use the session's existing transport; require explicit pruning permission; and fail closed while the runner is absent. No alternative lock or transport architecture is needed.

The strongest case for accepting is that this node only introduces a hook. Rsync arguments, actual copying, and transport-specific cleanup properly belong to add-rsync-before-keys. A real VM test and block-store proof would expand this node unnecessarily. I agree with those boundaries. The remaining issue is the shared hook contract and evidence for its advertised behavior, not the deferred copy implementation.

## Required before acceptance

1. **Define the runner failure boundary and timeout ownership.** design.md:43–48 specifies only a callable installed by the child. Specify its inputs, return/failure shape, and how it receives the selected session/transport. State declaration-order execution and stopping at the first failure. Specify who bounds execution and normalizes expected launch/transport exceptions and timeouts to pi-stage-failed, with no write_prompt or submit. This matters because pi_tmux.py:285 starts the existing timeout clock only after submission; it cannot bound a stage inserted before write_prompt. spawn.py:615–616 releases the lock on an exception, but does not turn an escaping runner exception into the promised face, and cannot release a lock while a runner hangs. Runner-owned timeout and exception normalization is a reasonable answer; this node need not implement rsync or a generic cancellation framework.

2. **Make focused verification cover the shipped failure path and integration seam.** tasks.md:9 promises only failed step, zero step, and no declaration. That can pass even if cmd_stage loses the declaration, run_pi never forwards it, or the new turn status falls through to pi-session-unreachable (spawn.py:636–642). Add explicit packet-to-spec-to-turn and face assertions, particularly non-empty stage with no registered runner, which is this node's initial production behavior. Use event-recording fakes to check lock/idle/stage/write_prompt/submit ordering, empty-stage compatibility, first-failure short circuit, and no stage on a dirty composer or unavailable lock. Include the agreed runner error/timeout path. Check old-packet validity and rejection of malformed stage entries in the schema. These are focused contract checks, not a suite-wide or remote-copy gate.

## Nonblocking implementation concern

The schema shape is appropriately constrained, but cmd_stage currently loads JSON without validating the full packet (spawn.py:277–285), and cmd_run loads spec.json directly (846–848). The implementer should make the validation boundary explicit so malformed declarations are rejected rather than treated as absent through truthiness. In particular, missing dest or a string-valued delete must not acquire defaults or pruning semantics. A stage-specific check suffices; redesigning packet validation is unnecessary.
